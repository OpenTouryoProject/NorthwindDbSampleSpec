## DEC-ORD-01 送料の欄が空のまま保存されたとき

| 項目 | 内容 |
| :--- | :--- |
| 対象 | `SC-ORD-03-I09`（受注登録・編集の送料）、`SC-ORD-04-I07`（出荷更新の送料） |
| 問い | 送料の欄（必須でない）が空のまま保存されたとき、`Orders.Freight` に何を保存するか |
| 選択肢 | 1. 0 として保存する ／ 2. NULL として保存する |
| 決定 | 1。空のまま保存した場合は 0 として保存する |
| 理由 | 仕様の中に `Freight` が NULL になる入り口があった。[DEC-CMN-03](./Common.md#dec-cmn-03-送料が-null-の受注の合計)（NULL は 0 として足す）とあわせて、入り口も塞ぐ |
| 決めた日 | 2026-11-06 |

## DEC-ORD-02 検索結果が 0 件のときのページ情報

| 項目 | 内容 |
| :--- | :--- |
| 対象 | `SC-ORD-01-I08`（ページ情報「n / m ページ」） |
| 問い | 検索結果が 0 件のとき、総ページ数を 0 とするか 1 とするか |
| 選択肢 | 1. 「1 / 1 ページ」（総ページ数は最小 1） ／ 2. 「0 / 0 ページ」 ／ 3. ページ情報を表示しない |
| 決定 | 1。総ページ数は最小 1 とし、0 件のときは「1 / 1 ページ」を表示する |
| 理由 | `EV-ORD-102` 手順 3 で現在ページは 1 に戻るので、表示と保持しているページ番号が食い違わない。移動のボタン（`SC-ORD-01-B05`）は活性条件により全部非活性になる |
| 決めた日 | 2026-11-08 |
| 出どころ | #3（受注一覧のページ切替のテスト。OpenTouryoProject/OpenTouryoCodingAgentAssets#8） |

## DEC-ORD-03 検証エラーで検索を中断したときの一覧

| 項目 | 内容 |
| :--- | :--- |
| 対象 | `EV-ORD-102` 手順 1（「エラーがある場合は処理を中断する」）、`EV-ORD-104` 入力（保持された検索条件） |
| 問い | `VAL-DATE` 違反などで検索を中断したとき、直前の一覧を残すか消すか |
| 選択肢 | 1. 直前の一覧を残す ／ 2. 一覧を消す（0 件のときと同じ表示） |
| 決定 | 1。一覧・総件数・ページ情報と「一覧状態の保持」は更新せず、直前の表示のまま残す。入力欄は入力した値のまま。以後のページ切替は、保持された直前の検索条件で行う |
| 理由 | `ERR-VALIDATION`（共通仕様 7 節）の「入力値を保持したまま画面に留まる。更新は行わない」と、中断により手順 5（一覧状態の保持）に進まないことに合う |
| 決めた日 | 2026-11-08 |
| 出どころ | #3 |

## DEC-ORD-04 保持する検索条件

| :--- | :--- |
| 対象 | `EV-ORD-104` 入力（「保持された検索条件」）、`EV-ORD-102` 手順 5 |
| 問い | ページ切替で使う検索条件は、入力欄の今の値か、最後に実行した検索の条件か |
| 選択肢 | 1. 最後に実行した検索の条件 ／ 2. 入力欄の今の値 |

## DEC-ORD-06 移動先のページが無くなっていたとき

| 項目 | 内容 |
| :--- | :--- |
| 対象 | `EV-ORD-104`（手順 1・3）、`SC-ORD-01-I06`・`SC-ORD-01-I08` |
| 問い | `EV-ORD-104` は手順 1 で前回の総ページ数を使って移れるかを判定し、手順 3 で検索し直して総件数を取り直す。その間に受注が消され、移動先のページが無くなっていたとき（例：2 ページ目へ移ったが、検索し直すと 1 ページ分しかない）、何を表示するか |
| 選択肢 | 1. 空の一覧を「2 / 1 ページ」と表示する ／ 2. 最終ページを表示する ／ 3. 1 ページ目に戻す ／ 4. 取り直した総ページ数で判定し直し、移らずに今の表示のままにする |
| 決定 | 2。取り直した総ページ数の最終ページを表示する。保持しているページ番号も最終ページにする（`EV-ORD-104` 手順 4） |
| 理由 | 1 は表示と保持しているページ番号が食い違う（[DEC-ORD-02](#dec-ord-02-検索結果が-0-件のときのページ情報) と同じ考え方）。3 は利用者がいた位置から離れすぎる。4 は件数が減ったのに画面が古いまま残る |
| 決めた日 | 2026-11-08 |
| 出どころ | OpenTouryoProject/OpenTouryoCodingAgentAssets#10（受注一覧のテスト仕様で決めた） |

## DEC-ORD-07 受注日に時刻があるときの範囲と並び

| 項目 | 内容 |
| :--- | :--- |
| 対象 | `EV-ORD-102` の「受注検索クエリ」（受注日終了：`Orders.OrderDate <= 終了日`）、`SC-ORD-01-I04`（「当該日を含む」）、`SC-ORD-01-I06`（既定の並び「受注日の降順、同日は受注 ID の降順」） |
| 問い | `Orders.OrderDate` は `datetime` で、時刻を持つ行がありうる。(a) クエリの文字どおりでは終了日の 15:30 の受注が含まれないが、画面定義書は「当該日を含む」とする。含めるか (b) 並びの「同日」は、日付だけで比べるか、時刻まで比べるか |
| 選択肢 | (a) 1. 日付の単位で比べ、終了日の当日の終わりまで含める ／ 2. 文字どおり終了日の 00:00 以前（当日の時刻付きの受注は含まない）<br>(b) 1. 日付の単位で比べる（同じ日なら時刻に関係なく受注 ID の降順） ／ 2. 時刻まで比べる（同じ日でも時刻の新しい順。同じ日時のときだけ受注 ID の降順） |
| 決定 | (a) 1、(b) 1。受注日の範囲と並びは、どちらも日付の単位で比べる。終了日の受注は時刻に関係なく含め、同じ日の受注は時刻に関係なく受注 ID の降順に並べる |
| 理由 | 画面定義書の「当該日を含む」「同日」という語に合う。画面の入力は日付だけで、利用者は時刻を意識しない |
| 決めた日 | 2026-11-08 |
| 出どころ | OpenTouryoProject/OpenTouryoCodingAgentAssets#10（受注一覧のテスト仕様で決めた） |

| 問い | 既定の並びで、受注日が NULL の受注を先頭と末尾のどちらに置くか |

## DEC-ORD-09 受注日の検索条件の形式と、読めないときの文言

| 項目 | 内容 |
| :--- | :--- |
| 対象 | `SC-ORD-01-I03`・`SC-ORD-01-I04`（受注日の開始・終了）、`VAL-DATE`（日付として解釈できること）、共通仕様 4 節（日付の入力は `yyyy/MM/dd`）、[DEC-CMN-01](./Common.md#dec-cmn-01-メッセージの定め方) |
| 問い | 仕様にある `VAL-DATE` の文言は前後関係の違反だけで、日付として読めない入力（例 `abc`）の文言が無い。また `2198/1/5`・`2198-01-05`・存在しない日付 `2199/02/30`・空白だけの入力を受け付けるかが決まっていない |
| 選択肢 | 形式と文言：1. `yyyy/MM/dd` の形だけを受け付け、新しい文言を決める ／ 2. 日付として読めれば形は問わず受け付け、読めないときの文言だけ決める ／ 3. 前後関係の違反の文言を流用する<br>空白だけの入力：1. 未指定とみなす ／ 2. エラーにする |
| 決定 | 形式と文言は 1。`yyyy/MM/dd` の形で、存在する日付だけを受け付ける（`2198/1/5`・`2198-01-05`・`2199/02/30` は違反）。違反のときは「受注日は yyyy/MM/dd の形式で指定してください。」と表示する（開始・終了で同じ文言）。空白だけの入力は 1（未指定とみなす） |
| 理由 | 共通仕様 4 節が日付の入力を `yyyy/MM/dd` と定めている |
| 決めた日 | 2026-11-08 |
| 出どころ | OpenTouryoProject/OpenTouryoCodingAgentAssets#10（受注一覧のテスト仕様で決めた） |

## DEC-ORD-10 datetime の下限より前の受注日の検索条件

| 項目 | 内容 |
| :--- | :--- |
| 対象 | `EV-ORD-102` の検証内容（`VAL-DATE`）、[DEC-ORD-09](#dec-ord-09-受注日の検索条件の形式と読めないときの文言) |
| 問い | 1753/01/01 より前の日付（例 `1000/01/01`）は DEC-ORD-09 の形式（`yyyy/MM/dd` の存在する日付）としては受け付けるが、SQL Server の `datetime` が持てない。実装しだいで、DB エラー（`ERR-DB` 扱い）か 0 件になる。どう扱うか |
| 選択肢 | 1. 定めない（実装に任せ、テストの期待にしない） ／ 2. `1753/01/01` 以降だけを受け付け、それより前は DEC-ORD-09 の文言にする ／ 3. それより前は専用の文言を決める |
| 決定 | 1。定めない。実装に任せ、テストの期待にしない |
| 理由 | サンプルの利用者が入力する範囲ではなく、他の決定に影響しない |
| 決めた日 | 2026-11-13 |
| 出どころ | OpenTouryoProject/OpenTouryoCodingAgentAssets#10（受注一覧のテスト仕様（MVC_Sample）で決めた） |

## DEC-CMN-01 メッセージの定め方

| 項目 | 内容 |
| :--- | :--- |
| 対象 | 共通仕様 7 節（`ERR-*`）、`EV-ORD-102` の検証内容（`VAL-DATE` 違反のメッセージ） |
| 問い | メッセージを ID で定めるか、文言で定めるか（`VAL-DATE` 違反のメッセージには文言だけがあり、ID が無い） |
| 選択肢 | 1. 文言で定め、メッセージ ID は実装で決める ／ 2. 仕様でメッセージ ID の体系を定め、各メッセージに ID を振る |
| 決定 | 1。メッセージは文言で定める。メッセージ ID は実装で決め、共通仕様・各設計書では定めない |
| 理由 | 共通仕様 2 節の ID 体系にメッセージ ID は無く、仕様は全体を通してメッセージを文言で決めている（`ERR-DB`・`EV-ORD-108`・`OD-T1` など）。漏れではなく、決まりが書かれていなかった |

## DEC-CMN-02 明細が無い受注の小計

| 項目 | 内容 |
| :--- | :--- |
| 対象 | 共通仕様 3 節「金額の算出式」、`EV-ORD-101`・`EV-ORD-102` の「受注検索クエリ」（合計金額） |
| 問い | `Order Details` が 0 件の受注の小計・合計をどうするか |
| 選択肢 | 1. 小計は 0（合計 = 0 + 送料） ／ 2. 合計を NULL（空欄）にする ／ 3. 一覧から除く |
| 決定 | 1。明細が無い受注の小計は 0 とする |
| 理由 | 空の和は 0。`ORD-T5` により本システムの登録では起きないが、「DB は妥当性を保証しない」方針（共通仕様 6 節）のため、`ORD-T5` に反するデータは起こりうる。一覧から隠さない |
| 決めた日 | 2026-11-06 |
| 出どころ | #2 |

## DEC-CMN-03 送料が NULL の受注の合計

| 項目 | 内容 |
| :--- | :--- |
| 対象 | 共通仕様 3 節「金額の算出式」（受注合計 = 小計 + `Orders.Freight`） |
| 問い | `Orders.Freight` が NULL のとき、受注合計をどうするか（`Freight` は NULL 可、既定 0） |
| 選択肢 | 1. NULL は 0 として足す ／ 2. 合計も NULL（空欄）にする |
| 決定 | 1。`Orders.Freight` が NULL のときは 0 として受注合計に加える |
| 理由 | 今の DB に NULL の行は無いが、送料の欄は必須でなく、空で保存したときの扱いが未定で、仕様の中に NULL の入り口があった。計算の扱いを決め、入り口は [DEC-ORD-01](./Orders.md#dec-ord-01-送料の欄が空のまま保存されたとき) で塞ぐ |
| 決めた日 | 2026-11-06 |
| 出どころ | #2 |

## DEC-CMN-04 関連チェックの違反の表示先

| 項目 | 内容 |
| :--- | :--- |
| 対象 | 共通仕様 4 節（メッセージ表示・項目単位のエラー）、共通仕様 7 節 `ERR-VALIDATION`、`VAL-DATE`（`EV-ORD-102` の「開始 <= 終了」） |
| 問い | 2 つ以上の項目にまたがる検証（関連チェック。例：受注日の開始 <= 終了）の違反を、どこに表示するか。`ERR-VALIDATION` は「該当項目にエラー内容を表示」、4 節は「項目単位のエラーは該当入力項目の直下」「メッセージは共通メッセージ領域」とし、項目が 2 つあるときの表示先が決まらない |
| 選択肢 | 1. 後ろの項目（終了）の直下 ／ 2. 前の項目（開始）の直下 ／ 3. 関係する項目すべての直下 ／ 4. 共通メッセージ領域だけ ／ 5. 共通メッセージ領域と、関係する項目すべての直下 |
| 決定 | 4。関連チェックの違反は、共通メッセージ領域にだけ表示する。1 つの項目で決まる検証（項目単位の検証）の違反の表示先は [DEC-CMN-05](#dec-cmn-05-項目単位の検証の違反の表示先) |
| 理由 | 開始 <= 終了は関連チェックに当たるため。`ERR-VALIDATION` の「該当項目に表示」は、項目単位の検証に当てはめる |
| 決めた日 | 2026-11-08 |
| 出どころ | OpenTouryoProject/OpenTouryoCodingAgentAssets#10（受注一覧のテスト仕様で決めた） |

## DEC-CMN-05 項目単位の検証の違反の表示先

| 項目 | 内容 |
| :--- | :--- |
| 対象 | 共通仕様 4 節（メッセージ表示・項目単位のエラー）、共通仕様 7 節 `ERR-VALIDATION`、`VAL-DATE`（日付として解釈できること）、[DEC-CMN-04](#dec-cmn-04-関連チェックの違反の表示先)、[DEC-ORD-09](./Orders.md#dec-ord-09-受注日の検索条件の形式と読めないときの文言) |
| 問い | 1 つの項目で決まる検証（例：受注日（開始）に `abc`）の違反を、該当入力項目の直下に加えて共通メッセージ領域にも表示するか。4 節は「項目単位のエラーは該当入力項目の直下」とする一方、「画面上部の共通メッセージ領域に、情報／警告／エラーを区別して表示する」ともしていて、両方に出すかが決まらない |
| 選択肢 | 1. 該当入力項目（誤っている項目）の直下だけ ／ 2. 共通メッセージ領域だけ（DEC-CMN-04 と同じ扱い） ／ 3. 該当入力項目の直下と、共通メッセージ領域の両方 |
| 決定 | 1。項目単位の検証の違反は、該当入力項目の直下にだけ表示し、共通メッセージ領域には表示しない。複数の項目が誤っているときは、それぞれの直下に表示する |
| 理由 | 4 節の「項目単位のエラー」と `ERR-VALIDATION` の「該当項目に表示」がそのまま当てはまる。関連チェックを共通メッセージ領域だけに出す [DEC-CMN-04](#dec-cmn-04-関連チェックの違反の表示先) と対にする |
| 決めた日 | 2026-11-09 |
| 出どころ | OpenTouryoProject/OpenTouryoCodingAgentAssets#10（受注一覧のテスト仕様の段 2 のレビューで見つかった） |

## DEC-CMN-06 共通メッセージ領域に前の知らせがあるときのエラーの表示

| 項目 | 内容 |
| :--- | :--- |
| 対象 | 共通仕様 4 節（メッセージ表示）、`EV-ORD-101` 手順 7（0 件の知らせ）、[DEC-CMN-04](#dec-cmn-04-関連チェックの違反の表示先)、[DEC-ORD-03](./Orders.md#dec-ord-03-検証エラーで検索を中断したときの一覧) |
| 問い | 共通メッセージ領域に情報（例：0 件の「該当するデータがありません。」）が出ているときにエラー（例：受注日の開始 > 終了）を出すと、前の情報を残すか消すか。4 節は「情報／警告／エラーを区別して表示する」とするだけで、複数の知らせが重なるときを定めていない。DEC-ORD-03 が直前のまま残すとしたのは一覧・総件数・ページ情報で、メッセージは含まない |
| 選択肢 | 1. 前の知らせを消し、エラーだけを表示する ／ 2. 前の知らせを残し、エラーを加えて表示する ／ 3. 定めない（実装に任せる） |
| 決定 | 3。定めない。前の知らせを残すか消すかは実装に任せ、テストの期待にしない。エラーはエラーとして区別して表示する（4 節） |
| 理由 | 本文に手がかりが無く、どちらでも 4 節の「区別して表示する」を満たすため。決めるべき場面が出たら、この決定を取り消して決め直す |
| 決めた日 | 2026-11-11 |
| 出どころ | OpenTouryoProject/OpenTouryoCodingAgentAssets#10（受注一覧 MVC_Sample net48 で、情報とエラーの区別のテストを足す段 1 のレビューで見つかった） |

## 記載レベルの基準

詳細設計は「行間を残さない」ことを基準とする。具体的には次を満たすこと。

| # | 基準 |
| :--- | :--- |
| 1 | 画面項目には、データソース（`テーブル.列` または算出式）と制約を必ず記す |
| 2 | 算出項目は式で示す（「合計を表示する」ではなく `合計 = 小計 + 送料`） |
| 3 | イベントの処理内容は番号付きの手順とし、DB アクセスは対象テーブル・結合・抽出条件・並び順・件数まで記す |
| 4 | 検証内容とエラーハンドリングは、共通仕様の ID を参照したうえで個別分を列挙する |
| 5 | 更新系イベントはトランザクション境界と楽観排他の判定方法を明記する |
| 6 | 分岐（モード・状態・NULL の有無）はすべて記述し、実装者に判断を委ねない |

イベント仕様書の項目構成は次で固定する（元ネタの[記載レベル](https://raw.githubusercontent.com/OpenTouryoProject/CodingAgentPlayground/refs/heads/main/Copilot/NorthwindWebForms/SPEC1.md)に準拠）。

```
イベント概要 / トリガー条件 / 事前条件 / 入力 / 出力 / 処理内容 / 検証内容 / エラーハンドリング / 依存関係
```

## 実装スコープの制限

[共通仕様 1 節](../HLD/Common.md#設計スコープ作らないもの)のとおり、次は**実装しない**。設計書に登場しないものを推測で作らないこと。

- ワークテーブル、採番テーブル（採番は `IDENTITY`）
- 変更履歴・監査ログ、論理削除
- 非同期処理（帳票・印刷を含む）、ジョブ、キュー
- データ・キャッシュ層
- ドメイン駆動設計（DDD）に基づく戦術的パターン
- 認証・認可（[要件定義 3.2](../RDD/Home.md#32-スコープ外)）

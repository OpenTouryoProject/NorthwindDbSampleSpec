本書は索引と読み方を定める。各決定はモジュール別のファイルに分割している。

## 読み方

- **本文（要件定義・基本設計・詳細設計）は、意図的に不完全なまま保つ。** 本文の漏れ・曖昧さは、テストを起こすエージェントが仕様の漏れを見つけられるかを試す教材になる。
- 漏れに対して**決まったことは、本文に書き込まず、本書以下に記録する。** 実装・テストは、**本文と決定記録を合わせて読む**（決定記録が本文の該当箇所を補う）。
- 決定記録と本文が食い違うときは、決定記録を正とする。
- 教材としてやり直すときは、`LLD/EventSpec`・`LLD/UI_ElementsAndEventList` から該当する仕様を削除し、もう一度フォワードする。

## 記載項目

決定 1 件につき 1 節を設け、見出しは `DEC-<MOD>-nn <名前>` とする（`<MOD>` は[共通仕様 2 節](../HLD/Common.md#2-id-体系)のモジュール コード）。次の項目をこの順序で記す。

| 項目 | 内容 |
| :--- | :--- |
| 対象 | 補う本文の ID・節（例：`EV-ORD-104`、共通仕様 7 節） |
| 問い | 本文から決められなかったこと |
| 選択肢 | 検討した案。間引かずに列挙する |
| 決定 | 採った案 |
| 理由 | 本文のどこから、なぜそう決めたか |
| 決めた日 | YYYY-MM-DD |
| 出どころ | 漏れを見つけた issue・テスト |

ID は振り直さない。決定を取り消すときは節を消さず、決定の欄に「取り消し（日付・理由）」と書く。
